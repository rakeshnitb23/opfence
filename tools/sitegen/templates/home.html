Catalog

Versioned YAML rules for cloud APIs and MCP servers. Each operation gets a risk class (read, write, delete, irreversible, money, credential or access), and every verified rule replays a recorded request in CI. A nightly job compares the rules with the schemas providers publish.

How a decision is made

  1. Decode. REST, GraphQL, AWS SigV4, git over HTTPS, MCP JSON-RPC and tool calls are read into operations; SQL, Redis commands and AWS CLI lines inside tool calls are parsed too.
  2. Classify. The operation's rule gives its class, made stricter by its arguments (--skip-final-snapshot, DELETE without a limiting WHERE).
  3. Decide. Your policy maps the class and the environment the resource is in to allow, ask, confirm or deny. A repository's policy can only make it stricter.
