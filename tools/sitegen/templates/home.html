Stop your AI agent before it deletes production.

Opfence is the open list of things an agent must never do without asking, and the tool that enforces it.

Coding agents run with real cloud credentials. In April 2026 one deleted a startup's production database and its backups with a single API call. Opfence reads each request an agent makes, looks the operation up in a tested catalog, and decides whether it runs, waits for you, or is blocked.

Three parts, one catalog

Catalog

Versioned YAML rules for cloud APIs and MCP servers. Each operation gets a risk class: read, write, delete, irreversible, money, credential or access. Every verified rule replays a recorded request in CI, and a nightly job compares the rules with the schemas providers publish.

Browse every rule

Compiler

opfence export turns the catalog into policy for NVIDIA OpenShell, for Claude Code (permission rules and a PreToolUse hook that reads each tool call's arguments) and for MCP tool annotations.

Protect Claude Code

Runner

opfence run -- claude puts the agent behind a local proxy that holds your keys, swaps placeholders for them only on their own API, and asks before anything destructive, on your desktop or your phone.

How a decision is made

  1. DecodeREST, GraphQL, AWS SigV4, git over HTTPS, MCP JSON-RPC and tool calls become operations. SQL, Redis commands and AWS CLI lines inside tool calls are parsed too.
  2. ClassifyThe operation's rule gives its class, made stricter by its arguments: --skip-final-snapshot, or a DELETE with no WHERE that limits it.
  3. DecideYour policy maps the class and the resource's environment to allow, ask, confirm or deny. A repository's policy can only make it stricter.
